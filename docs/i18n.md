# Internacionalização (i18n) e localização (l10n)

## Arquitetura

- **`src/i18n/config.ts`** — Fonte da verdade. Define os 15 idiomas suportados, direção (LTR/RTL), moeda, primeiro dia da semana, sistema de medidas e helpers `normalizeLocale` / `localeByCountry`.
- **`src/i18n/index.ts`** — Bootstrap do `i18next` com **lazy loading** via `import.meta.glob("../locales/*/*.json")`. Cada namespace de cada idioma vira um chunk separado no build.
- **`src/i18n/detector.ts`** — Cadeia de detecção: `profile.locale → localStorage → navigator → timezone → IP (cf-ipcountry/x-vercel-ip-country) → DEFAULT_LOCALE`.
- **`src/i18n/detect-locale.functions.ts`** — Server function que lê o header de país já enviado pelo edge (sem chamar API externa).
- **`src/i18n/format.ts`** — Helpers `formatDate`, `formatCurrency`, `formatRelative`, etc, baseados em `Intl`.
- **`src/i18n/rtl.ts`** — `applyDocumentDirection(locale)` seta `lang` e `dir` no `<html>`.
- **`src/i18n/hooks.ts`** — `useLocale()` retorna locale ativo + formatters já vinculados.
- **`src/lib/i18n.ts`** — Fachada de compatibilidade (re-exporta de `@/i18n`). Componentes existentes continuam funcionando.
- **`src/components/i18n/locale-selector.tsx`** — Dropdown global. Persiste em `localStorage` sempre e, se houver sessão, em `profiles.locale`.

## Idiomas atualmente suportados

pt-BR (source), en (padrão global), es, fr, it, de, nl, pl, tr, **ar (RTL)**, ja, ko, zh-CN, zh-TW, ru.

## Namespaces

`common`, `landing`, `auth`, `app`, `pro`, `admin`, `ai`, `kid`. Novos namespaces devem ser adicionados a `NAMESPACES` em `config.ts` e criados em pelo menos `pt-BR/` e `en/`. Ausentes caem em cascata: idioma solicitado → EN → PT-BR.

## Ordem de detecção

1. `profile.locale` (persistido em Supabase e sincronizado em `LocaleSync`).
2. `localStorage["mma:locale"]`.
3. `navigator.language` / `navigator.languages`.
4. `Intl.DateTimeFormat().resolvedOptions().timeZone` (mapa fraco).
5. País pelo IP via headers de edge (`cf-ipcountry`, `x-vercel-ip-country`). **Sem GPS, sem permissão de geolocalização.**
6. `DEFAULT_LOCALE` (en).

## Como adicionar strings novas

1. Coloque a chave em `src/locales/pt-BR/<ns>.json` (fonte).
2. Espelhe em `src/locales/en/<ns>.json`.
3. Use `useTranslation("ns")` + `t("chave")` no componente. **Nada de string hardcoded em novas telas.**

## Como adicionar um novo idioma

1. Adicione a entrada em `LOCALES` (`src/i18n/config.ts`).
2. Crie `src/locales/<code>/common.json` (mínimo). Outros namespaces herdam via fallback até serem traduzidos.
3. Se for RTL, defina `dir: "rtl"`. O layout usa CSS logical properties do Tailwind e reage automaticamente.

## Formatação

Use sempre os helpers de `useLocale()` para datas, números, moedas. Nunca `toLocaleString()` com string fixa. Isso garante que Ramadã, calendários alternativos e moedas locais sejam respeitados no futuro.

## Tradução assistida por IA (próxima onda)

O gateway central (`src/modules/ai/gateway.ts`) já suporta chamadas ao Gemini. Um script `scripts/i18n-translate.ts` (a implementar) irá:

1. Ler `src/locales/pt-BR/*.json`.
2. Para cada idioma alvo, gerar chaves ausentes via Gemini com prompt fixo por namespace (mantém tom, respeita placeholders `{{name}}`).
3. Escrever no arquivo de destino sem sobrescrever chaves já traduzidas manualmente.

## RTL

Layout do shell usa `flex`/`grid` + utilities logical (`ms-`, `me-`, `ps-`, `pe-`) sempre que possível. Ícones direcionais (setas, chevrons) devem receber `rtl:rotate-180` quando fizerem sentido semanticamente.
